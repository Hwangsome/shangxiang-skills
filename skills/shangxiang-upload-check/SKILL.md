# 商详上传合规检查

平台的硬性规则（2026-10 实测报错得出）：

| 项目 | 要求 |
|---|---|
| 宽度 | ≥ 700 px |
| 高度 | ≥ 32 px |
| 宽 ÷ 高 | 0.5 – 32，也就是**高度 ≤ 宽度 × 2**（790 宽最高 1580） |
| 文件大小 | ≤ 2 MB |

注意：平台算的是比例，单纯压缩或放大分辨率解决不了“太高”的问题，必须把图切开或者左右补边。

## 怎么做

1. 先只出报告、不动文件，看看有多少张不合规：

   ```bash
   python scripts/fix_aspect_ratio.py --src <分图根目录> --out <合规输出目录> --dry-run
   ```

2. 再正式修复（需要 `numpy`、`Pillow`）：

   ```bash
   python scripts/fix_aspect_ratio.py --src <分图根目录> --out <合规输出目录> --mode split
   ```

   - `split`（默认，推荐）：超高的图在接近纯色的水平行处切成几张，每张高 ≤ 2 × 宽 × 0.98（留 2% 余量防止卡线）。宽度不变，上下拼接后看起来是连续的。
   - `pad`：张数不变，左右补边到满足比例。适合平台限制图片张数的情况，代价是内容会略缩小、两侧出现延伸色带。
   - `--only E1605`：只处理名字里含这个字符串的商品目录。
   - 已经合规的图原样拷贝，不重新编码。

3. 脚本最后会复检所有输出（`verify: total=… bad=…`），并写出 `_fix_report.csv`。告诉用户：多少张原样拷贝、多少张被切分，复检不合格数是否为 0。

## 提醒用户

切分会让每个商品的图片张数变多。如果用户的平台对单个商品的详情图张数有上限，先报告超出上限的商品，建议改用 `--mode pad`。
